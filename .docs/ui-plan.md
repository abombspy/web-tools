# UI 개선 계획 — "전체 메뉴를 한눈에 보기 어렵다" 문제

## 1. 문제 정의

사용자 피드백(2026-09-20): "서브 메뉴를 한번에 볼 수 있는 방법은 없을까? 어떤 기능이 있는지 찾기가 어려워서.."

현재 구조:
- 홈(`/`) → 8개 카테고리 카드(이름+설명+"둘러보기" 링크)만 보여줌. 하위 도구 이름은 홈에서 전혀 안 보임.
- 헤더 내비게이션 → 8개 카테고리 링크만 있음(하위 도구 링크 없음).
- 카테고리 랜딩 페이지(`/part-time` 등) → 그 카테고리의 도구 목록(5~6개)을 보여줌.

즉 지금은 **"카테고리 → 클릭 → 그 카테고리의 도구 목록"** 2단계를 거쳐야만 특정 도구가 존재하는지 알 수 있음. 전체 43개 도구가 뭐가 있는지 한 번에 훑어볼 방법이 없음. `Header.tsx`에도 "카테고리(및 하위 계산기)가 더 늘어나면 메가메뉴/아코디언 내비게이션으로 교체" TODO가 이미 있었음(plan.md §2.3, §7.3) — 예견됐던 문제.

## 2. 검토한 옵션

### 옵션 A. 전체 도구 페이지 신설 (`/all-tools`)
카테고리별로 43개 도구를 한 페이지에 전부 나열. 헤더에 "전체 도구" 링크 하나 추가.

- 장점: 구현 단순(반나절 이내), 기존 레이아웃 안 건드림, URL 하나 늘어서 SEO에도 도움(내부링크 밀도↑), 모바일에서도 그냥 세로 스크롤이라 반응형 걱정 적음.
- 단점: 여전히 홈/헤더에서 "전체 도구"를 클릭하는 한 번의 추가 이동이 필요함(다만 지금의 "카테고리 클릭 → 하위 목록" 2단계보다는 나음).

### 옵션 B. 홈페이지 자체를 확장
홈 화면에서 카테고리 카드 클릭 없이, 각 카테고리 아래에 하위 도구 이름을 바로 나열(현재 카테고리 소개문 대신/추가로).

- 장점: 진입 즉시(0클릭) 전체 목록이 보임. 별도 페이지 불필요.
- 단점: 홈이 매우 길어짐(카드 8개 × 도구 5~6개 = 40여 개 링크가 첫 화면부터 쏟아짐), 카테고리 소개 위주였던 홈의 성격이 바뀜, "이 사이트가 뭐하는 곳인지" 첫인상이 흐려질 수 있음.

### 옵션 C. 헤더 메가메뉴/드롭다운
헤더의 각 카테고리에 마우스오버(PC)/탭(모바일)하면 하위 도구가 드롭다운으로 펼쳐짐. 모든 페이지에서 항상 접근 가능.

- 장점: 가장 "매번 바로 보인다"는 목적에 충실. 페이지 이동 없이 어디서든 탐색 가능.
- 단점: 구현 복잡도 제일 높음(클릭/오버 상태 관리, 모바일 터치 UX, 접근성(키보드 포커스) 고려 필요). 헤더가 8개 카테고리라 드롭다운 8개를 관리해야 함.

### 옵션 D. 상시 노출 사이드바
문서 사이트처럼 왼쪽에 전체 카테고리/도구 트리를 상시 표시, 모바일에선 접이식.

- 장점: 가장 탐색성 높음(문서 사이트에 익숙한 사용자에게 친숙).
- 단점: 지금의 심플한 1단 레이아웃을 2단(사이드바+본문)으로 바꿔야 해서 전체 페이지(43개) 레이아웃에 영향, 계산기 자체의 좁은 본문 폭 설계와도 안 맞을 수 있음. 구현 범위가 제일 큼.

### 옵션 E. 검색/필터 박스
"계산기 이름으로 검색" 입력창(클라이언트 컴포넌트)을 홈이나 헤더에 배치, 타이핑하면 43개 중 필터링.

- 장점: 이름을 대충이라도 아는 사용자에게 제일 빠름.
- 단점: "뭐가 있는지 모르겠어서 둘러보고 싶다"는 지금 피드백의 핵심(탐색/발견) 문제는 검색만으로는 덜 풀림 — 목록형 UI와 같이 있어야 효과적.

### 옵션 F. 푸터에 전체 사이트맵 나열
모든 페이지 하단(Footer)에 카테고리별 전체 도구 링크를 나열.

- 장점: 모든 페이지에서 스크롤만 하면 보임, 크롤러 친화적(SEO 내부링크).
- 단점: 푸터가 매우 길어짐, "지금 보고 있는 페이지"와 무관하게 반복 노출되어 다소 장식적으로 느껴질 수 있음.

## 3. 권장안

**1차: 옵션 A(전체 도구 페이지) + 헤더에 링크 1개 추가**를 먼저 처리하고, **2차로 옵션 F(푸터 요약 링크)**를 가볍게 얹는 조합을 권장합니다.

이유:
- 지금 당장 필요한 건 "전체 목록을 한눈에 볼 창구 하나"이지, 모든 페이지에 상시 노출되는 무거운 내비게이션(C, D)까지는 아직 과할 수 있음 — 카테고리가 8개·도구가 43개인 지금 규모에서는 메가메뉴/사이드바는 "이 정도로 할 만큼 사이트가 커졌나?"를 다시 볼 필요가 있음.
- 옵션 B(홈 확장)는 "첫인상"이 바뀌는 게 커서, 별도 페이지로 분리하는 A가 더 안전한 변경.
- E(검색)는 목록형 UI(A)가 먼저 있어야 의미가 커지므로 후순위.
- A는 이미 초안을 `src/app/all-tools/page.tsx`로 만들어보고 있었음(카테고리별 섹션 + 도구 링크 그리드) — 계획 승인되면 이어서 마무리하면 됨.

## 4. 최종 결정 (2026-09-20)

사용자 확인: **옵션 B(홈페이지 카테고리 카드를 전체 목록으로 완전 교체) + 옵션 C(헤더 드롭다운 메뉴)**를 함께 적용.

- 홈(`/`): 지금의 "카테고리 이름+설명+둘러보기 링크" 카드 8개를 없애고, 카테고리 제목 아래 그 카테고리의 도구 링크를 바로 나열하는 구조로 교체(제안했던 옵션 B의 "완전 교체" 방식 — 카드와 하단 목록이 중복되는 걸 피함).
- 헤더(`Header.tsx`): 카테고리 8개 각각을 드롭다운으로 바꿔서, 어느 페이지에 있든 헤더에서 바로 원하는 도구로 이동 가능하게 함. 구현은 커스텀 JS 상태 관리 대신 `<details>/<summary>`(브라우저 네이티브 디스클로저 위젯)를 사용 — 자바스크립트 없이도 동작하고 접근성이 기본 제공되며, 정적 내보내기와도 완전히 호환됨.
- 별도 `/all-tools` 페이지는 만들지 않음(홈+헤더가 이미 같은 역할을 하므로, 굳이 만들면 완전히 겹치는 콘텐츠가 되어 애드센스 thin/중복 콘텐츠 리스크(§6.2)만 늘어남) — 초안으로 만들었던 `src/app/all-tools/page.tsx`는 삭제.
- sitemap.ts는 변경 불필요(새 경로가 생기는 게 아니라 기존 페이지들의 링크 구조만 바뀜).
