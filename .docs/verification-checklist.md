# Phase 1 계산기 검증 체크리스트

> plan.md §6.3(계산 정확성 검증 절차)을 실행하기 위한 문서. 각 계산기를 구현한 뒤
> 배포 전에 아래 공식 출처와 동일한 입력값으로 대조하고, 경계값 테스트를 통과해야 한다.
> 계산기별로 실제 검증을 마치면 상태를 `[ ]` → `[x]`로 표시한다.

## 알바·직장인

- [x] **주휴수당 계산기** — 공식(소정근로시간÷40×8×시급, 40시간 상한), 지급 조건(15시간 이상 + 개근)을 근로기준법 시행령 제30조 해설 자료로 교차검증 완료(2026-09-20). 경계값 단위 테스트 `src/lib/calculators/weekly-holiday-pay.test.ts` 5개 통과. 최저임금 10,320원은 고용노동부 고시 제2025-47호로 검증 완료(`config/rates/labor.json`). 단, 고용노동부 노동포털의 대화형 계산기와 1:1 수치 대조는 아직 안 함(형식적 확인만).
- [x] **알바 월급 계산기** — 가산수당(연장·야간·휴일) 공식·5인 미만 사업장 예외를 근로기준법 제56조·시행령 별표1로 교차검증. 4대보험 근로자 부담률(국민연금 4.75%, 건강보험 3.595%, 장기요양 건강보험료의 13.14%, 고용보험 0.9%)과 월 60시간 미만 적용제외 원칙을 웹 검색으로 교차검증(2026-09-20, `config/rates/labor.json`에 출처 기록). 소득세는 정확한 간이세액표 대신 "106만원 미만 0원" 임계값만 반영하고 그 이상은 계산하지 않도록 스코프를 의도적으로 제한(사용자 확인). 경계값 단위 테스트 `src/lib/calculators/part-time-wage.test.ts` 8개 통과, SSR 렌더링 값도 수동 재계산으로 대조 완료. 단, 고용노동부 노동포털 계산기와 1:1 대조 및 근로소득 간이세액표 정식 반영은 아직 안 함(후속 작업).
- [x] **퇴사 시점 비교 계산기** — 퇴직금 공식(평균임금×30×계속근로일수/365, 3개월 역일수 기준 평균임금 산정)과 연차 발생 기준(1년 미만 최대 11일, 3년차부터 2년마다 가산, 최대 25일)을 웹 검색으로 교차검증(2026-09-20). 연차 계산 로직은 `annual-leave-days.ts`로 공용화(연차수당 계산기와 재사용 예정). 경계값 단위 테스트: `annual-leave-days.test.ts` 8개, `resignation-comparison.test.ts` 4개 통과(근속 364일 vs 365일 경계, 3년차 가산 경계 등). 스코프 제한: 평균임금은 최근 3개월 월급이 동일하다고 가정(상여금·연차수당 등 비정기 수입 미반영), 미사용 연차수당 금액은 계산하지 않고 일수만 표시. 고용노동부 계산기와 1:1 대조는 아직 안 함.
- [x] **연차수당 계산기** — 연차 발생 로직은 `annual-leave-days.ts`를 그대로 재사용(퇴사 시점 비교 계산기와 동일 검증). 1일 통상임금 산식(월급÷209×8, 209=（40+8)×52÷12)을 웹 검색으로 교차검증(2026-09-20). 경계값 단위 테스트 `annual-leave-pay.test.ts` 4개 통과(사용 연차가 발생 연차 초과 시 0일 하한 등). 스코프 제한: 주 40시간 정규직 기준(단시간근로자 비례 연차는 미반영, UI에 명시). 고용노동부 계산기와 1:1 대조는 아직 안 함.
- [x] **실업급여 모의 계산기** — 2026년 1일 상한액(68,100원), 하한액 공식(최저시급×8×80%=66,048원), 소정급여일수 표(고용보험법 별표1, 나이×가입기간 구간)를 웹 검색으로 교차검증(2026-09-20, `config/rates/labor.json`에 출처 기록). 경계값 단위 테스트 `unemployment-benefit.test.ts` 8개 통과(하한액/상한액 적용 경계, 가입기간 1년 미만 120일 고정, 만 50세 경계에서 소정급여일수 증가). 스코프 제한: 수급 자격(비자발적 이직 등) 자체는 판단하지 않고 "자격이 있다고 가정한 금액"만 계산(UI에 명시). 고용보험 홈페이지 모의계산과 1:1 대조는 아직 안 함.
- [x] **육아휴직 급여 계산기** — 2026년 구간별 지급률·상한액(1~3개월 100%/250만원, 4~6개월 100%/200만원, 7~12개월 80%/160만원)과 하한액(70만원), 사후지급금 폐지(2025년 1월~) 사실을 두 개의 독립 출처로 교차검증(2026-09-20). 경계값 단위 테스트 `parental-leave-pay.test.ts` 5개 통과(하한액 보장, 3→4개월 구간 전환 시 상한액 하락 케이스 포함). 스코프 제한: "6+6 부모육아휴직제" 특례는 별도 제도라 다루지 않음(UI에 명시). 고용보험 홈페이지 안내와 1:1 대조는 아직 안 함.

## 생활·주거

- [x] **대출 이자·상환 계산기** — 법령이 아닌 표준 금융 공식(원리금균등/원금균등)이라 별도 웹 조사 불필요. 경계값 단위 테스트 6개 통과(이자율 0% 경계, 마지막 회차 잔액 정확히 0, 원금균등 총이자가 원리금균등보다 항상 적음). SSR 기본값(1억원/4.5%/30년) 렌더링을 독립적으로 재계산해 대조(월 상환액 506,685원 일치; 총 상환액은 매달 반올림 누적으로 129원 차이 — 실제 상환 방식에 더 가까운 정상적 차이).
- [x] **전월세 전환율 계산기** — plan.md에 ⚠️로 남겨뒀던 "법정 상한 산정식"을 실제로 확인: min(한국은행 기준금리+2%p, 연 10%)이 정확한 공식임을 2개 독립 출처로 교차검증(2026-09-20). 기준금리는 자주 바뀌므로 사용자가 직접 입력(하드코딩 안 함). 경계값 단위 테스트 5개 통과(고정 10% 상한 발동 경계, 법정 상한 초과 여부 경계). SSR 기본값 렌더링 대조 완료(791,667원).
- [x] **전기요금 계산기** — 주택용 3단계 누진제 요금표(구간별 기본요금·전력량단가, 여름철 완화 기준)를 웹 검색으로 교차검증(2026-09-20)했으나 공식 한전 페이지 원문 대조는 아직이라 `verified: false`로 표시. 부가세·기금은 추정치이며 실제 청구서의 10원 단위 절사 규칙은 미반영(스코프 제한, UI 명시). 경계값 단위 테스트 5개 통과(구간 경계 200kWh, 3단계 진입 시 기본요금 전환, 여름철 완화 효과, 사용량 0). SSR 기본값(350kWh, 7월) 렌더링 대조 완료(54,951원).
- [x] **이사 비용 견적 계산기** — plan.md §6.4에서 이미 "공식 요율표 없음"으로 예고한 대로, 한국소비자원 등 공식 통계는 확인되지 않음(웹 검색으로 재확인, 2026-09-20). 업체 블로그의 편차 큰 자료(원룸 포장이사 30만~50만원 등)를 참고해 단일 숫자가 아닌 **범위**로 결과를 표시하고, "반드시 실제 견적 비교" 안내를 강하게 노출해 허위 정밀도를 피함. 경계값 단위 테스트 5개 통과(최소비용 하한 적용, 사다리차 가산, 방식별 가격 순서). SSR 기본값 렌더링 대조 완료(48만~78만원).
- [x] **중개수수료 계산기** — 서울시 공식 부동산 포털(land.seoul.go.kr)에서 매매·임대차 구간별 상한요율·한도액 표 전체를 확인(2026-09-20), `verified: true`. 월세 환산보증금 공식(보증금+월세×100, 5천만원 미만 시 ×70)도 함께 확인. 경계값 단위 테스트 6개 통과(5천만원 정각 구간 전환, 한도액 적용, 환산보증금 재계산 경계). 지자체별 조례 차이는 스코프 밖으로 명시(UI 안내). SSR 기본값 렌더링 대조 완료(1,200,000원).

## 프리랜서·사업자

- [x] **3.3% 원천징수 역산 계산기** — 소득세 3% + 지방소득세(소득세의 10%) 구조는 법령상 고정값이라 별도 웹 조사 없이 구현(소득세법·지방세법). 지방소득세를 "세전의 0.3%"가 아니라 "소득세액의 10%"로 정확히 계산하도록 구현(원 단위 반올림 정합성). 세후→세전 역산은 근사치임을 명시. 경계값 단위 테스트 5개 통과(0원, 왕복 오차 ≤1원). SSR 기본값(세전 100만원→세후 967,000원) 렌더링 대조 완료.
- [x] **부가세 계산기** — 부가세율 10%는 수십 년째 고정된 법령값이라 별도 웹 조사 없이 구현(부가가치세법). 합계→공급가액 역산 시 "공급가액+부가세=합계"가 항상 정확히 성립하도록 구현(반올림 오차를 부가세 쪽으로 흡수). 경계값 단위 테스트 4개 통과. SSR 기본값(공급가액 100만원→합계 110만원) 렌더링 대조 완료.
- [x] **종합소득세 예상 계산기** — 종합소득세 누진세율표(8단계, 2023~2025년 귀속, 2026년 개정분 국세청 미게시)는 국세청 공식 페이지에서 직접 확인(2026-09-20). 업종 5개(1인미디어/저술가/학원강사/배달라이더/IT프리랜서)의 경비율은 여러 세무 블로그를 교차 검색해 확보했으나 기준 연도가 업종마다 다름(2019~2024년)과 **2026년 귀속 경비율은 2027년 4월에야 고시된다는 사실**을 확인 — `verified: false`로 명시하고 UI에도 안내함. 목록에 없는 업종은 사용자가 직접 경비율을 입력하도록 스코프를 제한(사용자 확인). 경계값 단위 테스트 6개 통과(단순/기준경비율 전환 경계, 세율 구간 경계, 과세표준 0원 하한). SSR 기본값(연매출 3천만원, 1인미디어, 기준경비율 적용) 렌더링 대조 완료(2,335,500원). 국세청 홈택스 모의계산과 1:1 대조는 아직 안 함.
- [x] **배달 라이더 순수익 계산기** — 플랫폼 수수료율을 하드코딩하지 않고 사용자 직접 입력으로 스코프를 제한해 데이터 조사 리스크(plan.md §6.4)를 원천 제거. 3.3% 원천징수는 기존 `withholding-tax-3-3.ts` 로직을 재사용(중복 구현 없음). 경계값 단위 테스트 4개 통과(수수료 0%, 비용>수입 시 음수 허용). SSR 기본값 렌더링 대조 완료(396,240원).
- [x] **스마트스토어·쿠팡 마진 계산기** — 카테고리별 수수료율을 하드코딩하지 않고 사용자 직접 입력으로 스코프를 제한(위와 동일 원칙, plan.md §6.4 리스크 해소). 판매가→마진율 정방향과 목표마진율→필요판매가 역방향 모두 지원. 경계값 단위 테스트 5개 통과(수수료 합+마진율이 100% 초과 시 에러, 판매가 0원 시 0으로 나누기 방지). SSR 기본값 렌더링 대조 완료(8,100원/27.0%).
- [x] **해외직구 관세 계산기** — 목록통관 면세한도(일반 150달러/미국발 200달러, 목록통관 배제품목 예외)와 "초과 시 전체 금액 과세(공제 없음)" 원칙을 웹 검색으로 교차검증(2026-09-20, `config/rates/tax.json`에 출처 기록). 스코프 제한: 관세율(품목별 HS코드)과 환율은 사용자 직접 입력, 개별소비세는 미반영(사용자 확인). 경계값 단위 테스트 6개 통과(면세한도 경계 1달러 차이로 과세 전환되는 절벽 효과, 미국발+목록통관제외 조합). SSR 기본값(140달러, 면세) 렌더링 대조 완료. 관세청 홈페이지 관세 계산기와 1:1 대조는 아직 안 함.

## 육아·건강

- [x] **출산 예정일 계산기** — 네겔레 법칙(마지막 생리일+280일)은 의학적으로 표준화된 공식이라 별도 웹 조사 불필요. 경계값 단위 테스트 5개 통과(임신 주수 경계, 예정일 초과 시 음수 표시).
- [x] **BMI·기초대사량·목표 칼로리 계산기** — 대한비만학회 2022 진료지침의 한국(아시아)인 BMI 기준(18.5/23/25/30/35, WHO 국제기준과 다름)을 웹 검색으로 확인·반영(2026-09-20). 기초대사량은 Mifflin-St Jeor 공식(안정적인 학술 공식). 경계값 단위 테스트 7개 통과(BMI 구간 경계 전부). SSR 기본값 렌더링 대조 완료(BMI 22.5, 목표 칼로리 2,155kcal).
- [x] **음주 후 해독 시간 추정기** — 위드마크 공식 구현 중 **체중을 kg 그대로 써서 BAC가 1000배로 부풀려지는 단위 버그를 테스트 작성 중 발견·수정**(체중을 g 단위로 환산해야 함). 회귀 테스트로 재발 방지. 경계값 단위 테스트 5개 통과(성별 계수 차이, 체중과 BAC의 반비례 관계).
- [x] **이유식 단계별 양 계산기** — 정부 공식 기준표는 없어 소아과·육아 정보 자료 교차 검색으로 4단계(초기/중기/후기/완료기) 급여 횟수·양 범위를 확보(2026-09-20). 경계값 단위 테스트 4개 통과(단계 전환 월령 경계).
- [x] **아기 개월수·성장 백분위 계산기** — **스코프를 의도적으로 축소**: 정확한 WHO 백분위는 LMS 파라미터 방대한 표가 필요해 재현하지 않고, "3~97백분위 범위의 중간값 대비 비교"로 한정(UI에 명확히 고지, 0~24개월만 지원). 경계값 단위 테스트 6개 통과(정확한 기준점, 선형 보간, 24개월 초과 시 고정).

## 날짜·시간

- [x] **D-day·기념일 계산기** — 순수 날짜 차이 계산이라 조사 불필요. 경계값 단위 테스트 3개 통과(당일, 미래, 과거).
- [x] **만 나이·띠·별자리 계산기** — 만 나이는 기존 `fullYearsBetween` 재사용. 띠는 음력 설날/입춘 기준이 정확하다는 걸 확인했으나 정밀한 절기 계산이 불가능해 "양력 1월 1일 기준 간이 계산"으로 스코프를 의도적으로 축소하고 UI에 명확히 고지(사용자 확인 없이 직접 판단, 재미 요소라 리스크 낮다고 판단). 별자리 날짜 구간은 표준적으로 통용되는 값 사용. 경계값 단위 테스트 7개 통과(별자리 월 경계 3곳, 띠 12년 주기, 음수 나머지 처리).
- [x] **군 전역일 계산기** — 2026년 기준 복무기간(육군·해병대 18개월/해군 20개월/공군 21개월/사회복무요원 21개월)을 웹 검색으로 확인(2026-09-20). 병역법 개정 가능성이 있어 향후 재검증 필요(UI에 명시). 경계값 단위 테스트 6개 통과(입대일 0%, 전역일 100%, 상하한 클램프).
- [x] **근무일수(영업일) 계산기** — 2026년 공휴일 전체 목록을 웹 검색으로 확보(`config/holidays/2026.json`). 자료에 잘못 포함되기 쉬운 근로자의날(5/1)과 제헌절(7/17, 2008년부터 공휴일 아님)을 의도적으로 제외해 정확도를 높임 — 이 두 개를 넣는 실수가 흔하다는 것도 확인. `verified: false`로 표시(설날·추석·대체공휴일은 매년 바뀜). 경계값 단위 테스트 5개 통과(평일 중 공휴일 집계, 공휴일이 주말과 겹칠 때 중복 집계 방지).
- [x] **시차 계산기** — 오프셋을 하드코딩하지 않고 JS 런타임의 IANA 타임존 데이터(Intl API)를 그대로 사용해 서머타임(DST)까지 날짜별로 정확히 반영 — 별도 데이터 검증이 필요 없는 설계. 경계값 단위 테스트 5개 통과(서울 무DST 확인, 뉴욕 겨울/여름 오프셋 차이, 서울-도쿄 시차 0).

## 학생·수험생

- [x] **내신·수능 등급 환산 계산기** — 2026년이 내신 등급제 전환기(고3은 9등급제 마지막 세대, 고1·고2는 5등급제)라는 걸 웹 검색으로 확인(2026-09-20), 5등급제(10/34/66/90/100)와 9등급제(4/11/23/40/60/77/89/96/100) 누적 비율표를 각각 확보. 수능은 표준점수가 아니라 백분위 입력만 지원(표준점수→등급은 매년 등급컷이 달라 정확히 계산 불가하다는 점을 사용자에게 설명 후 이 방식으로 진행). 경계값 단위 테스트 7개 통과(등급 구간 경계 다수).
- [x] **학점 평균(GPA) 계산기** — 한국 대학 표준 4.5 만점 척도는 안정적인 관행이라 별도 조사 불필요. 경계값 단위 테스트 4개 통과(과목 0개 시 0으로 나누기 방지, F학점 처리). SSR 기본값 렌더링 대조 완료(4.5만점 4.0, 4.3만점 3.82).
- [x] **공무원 시험 합격선 비교 도구** — **스코프를 크게 축소**: 미실시 시험의 "예상 커트라인"은 학원·블로그의 추측치뿐이라(웹 검색으로 확인, 2026-09-20) 특정 숫자를 내장하지 않고, 사용자가 직접 조사한 과거 합격선을 입력해 본인 점수와 비교하는 도구로 재설계(이름도 "예측기"에서 "비교 도구"로 변경). 경계값 단위 테스트 4개 통과.
- [x] **토익·오픽 점수 환산표** — 공공기관 채용 공고 첨부문서인 공식 "어학성적 환산 기준표"(OPIc 레벨별 TOEIC 구간·평균점수)를 PDF 원문으로 직접 확인(2026-09-20). 원본 표 자체의 구간 경계 중복(예: 815점이 IM2·IM3 양쪽에 걸침)과 빈틈(716~719점 미정의)을 그대로 반영하고 UI에 안내. 경계값 단위 테스트 5개 통과.

## 텍스트·파일 도구

> 이 카테고리는 법령·요율 검증이 아니라 "처리 결과가 정확한가"가 핵심이다. 실제 라이브러리(qrcode, pdf-lib) 호출까지 포함한 테스트로 검증했다.

- [x] **글자수 세기** — 순수 텍스트 통계라 조사 불필요. 서로게이트 쌍(이모지) 처리가 naive `.length`와 다르다는 점을 테스트로 확인. 경계값 단위 테스트 5개 통과.
- [x] **JSON·CSV 변환기** — RFC 4180 기준으로 직접 구현(따옴표 안 쉼표·줄바꿈·이스케이프된 따옴표 처리). 왕복 변환(객체→CSV→객체) 테스트로 정보 손실 없음을 확인. 단위 테스트 9개 통과. SSR 기본값 렌더링 대조 완료.
- [x] **QR코드 생성기** — `qrcode`(ISO/IEC 18004 표준 구현) 라이브러리 사용, 실제 데이터 URL 생성까지 테스트로 검증(빈 텍스트 에러 처리 포함). 단위 테스트 3개 통과.
- [x] **이미지 압축·리사이즈·포맷 변환** — Canvas API 기반(신규 라이브러리 불필요). 비율 유지 리사이즈 계산 로직만 분리해 단위 테스트 4개 통과(원본이 이미 한도 안이면 확대하지 않음 등 경계값). 실제 인코딩(Canvas.toBlob)은 브라우저 전용이라 자동 테스트 범위 밖 — 수동 브라우저 확인 권장.
- [x] **PDF 병합·분할** — `pdf-lib` 사용, 테스트에서 실제로 PDF를 생성·병합·분할까지 수행해 페이지 수를 검증(라이브러리 호출 자체를 신뢰성 있게 확인). 단위 테스트 7개 통과(범위 경계, 파일 1개 이하 시 에러 등).
- [x] **맞춤법 체크용 텍스트 정리 도구** — **스코프를 의도적으로 축소**: 진짜 맞춤법 검사(띄어쓰기, 문맥 의존 표현)는 신뢰할 공식 API가 없어(plan.md §6.4) 제외하고, 공백·줄바꿈 정리와 "됬→됐" 등 문맥과 무관하게 항상 틀린 오타 몇 개만 교정하도록 제한(UI에 명확히 고지). 단위 테스트 6개 통과.

## 재미·바이럴

> 계산 정확성보다 "정직한 재미"가 기준이다 — 과학적 근거가 없다고 명시된 항목에 근거 있는 척하는 숫자를 넣지 않았는지 확인한다.

- [x] **이름 궁합·MBTI 궁합 테스트** — 해시 기반 결정적 점수(같은 입력→항상 같은 결과, 순서 무관)로 구현하고 "과학적 근거 없음"을 UI에 명시. 단위 테스트 5개 통과(결정성, 대칭성, 범위, 코멘트 구간 경계).
- [x] **랜덤 추첨기·사다리타기·룰렛** — `Math.random()` 대신 `crypto.getRandomValues()` 사용(plan.md에서 이미 권장한 대로). 단위 테스트 9개 통과(범위, 빈 목록 에러, 셔플 원소 보존·불변성, 매칭 개수 불일치 에러). "사다리타기"는 실제 사다리 그림 없이 무작위 1:1 매칭으로 구현했음을 UI에 명시.
- [x] **점심 메뉴 추천 룰렛** — 랜덤 추첨기와 같은 `pickRandom` 로직 재사용, 메뉴 데이터만 추가(중복 로직 없음).
- [x] **닉네임 생성기** — 형용사+명사 목록에서 `pickRandom` 재사용. 단위 테스트 1개로 항상 정의된 단어 조합만 나오는지 확인.
- [x] **추천 조합** — 계산 로직 없는 내부 링크 허브 페이지. 6개 조합, 총 20개 링크를 실제로 전부 curl해서 200 응답 확인(오타로 죽은 링크 없음).

## 공통 절차

1. 계산기 구현 후, 위 공식 출처에 동일한 입력값을 넣어 결과가 일치하는지 확인한다.
2. 위에 나열된 경계값 케이스를 단위 테스트로 작성한다.
3. 두 항목 모두 통과해야 배포한다. 불일치가 있으면 plan.md §4의 계산 근거 설명을 먼저 재검토한다.
4. 매년 요율 개정 시(plan.md §6.6) 이 체크리스트를 다시 돈다.
